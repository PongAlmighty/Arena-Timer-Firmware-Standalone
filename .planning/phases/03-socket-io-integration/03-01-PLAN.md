<objective>
Upgrade WebSocketClient from Phase 2's local-only stub to a fully bidirectional Socket.IO integration with echo suppression and timer sync correction.

Three surgical changes land all three SYNC requirements:
1. SYNC-01 (D-01/D-02/D-03): emitTimerControl() emits 42["timer_control",...] before calling the local timer method; skips emit when offline so buttons still work standalone.
2. SYNC-02 (D-04/D-05/D-06): After each emit, store (_suppressAction, _suppressUntilMs). At the top of handleTimerUpdate(), consume and discard the echo on first match within 500ms.
3. SYNC-03 (D-07 through D-12): On runtime start, immediately start the local timer then send request_timer_status (with timer_id:1 — critical). On receiving timer_status, apply setDuration+reset+start from time_left. Skip the round-trip on initial connect sync (tracked by _initialSyncPending). Guard heartbeat start events from triggering a 5-second polling flood.

Purpose: Closes the last loop — box ref button presses propagate to FightTimer, FightTimer echoes don't cause double-triggers, and the ~1s startup offset from starting at full duration is eliminated.

Output: Two modified files. No new files, no new libraries, no main.cpp changes.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-01 | Tampering | handleWebSocketEvent() timer_status branch | mitigate | ArduinoJson `\| 0` default for time_left field; if absent/wrong type defaults to 0; the `if (time_left > 0)` guard prevents setDuration(0,0,0)+reset+start from running on a missing field |
| T-03-02 | Denial of Service | handleTimerUpdate() echo loop | mitigate | SYNC-02 one-shot suppression directly addresses FightTimer broadcast echo re-triggering local timer; suppression window is 500ms action-matched |
